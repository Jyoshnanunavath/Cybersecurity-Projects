How scoring works

Each password is checked against five rules — length, uppercase, lowercase, numbers, and special characters. The number of rules passed maps to a level: Weak (0–2), Medium (3), Strong (4), or Very Strong (all 5, with 12+ characters for the highest confidence). Nothing you type here is stored or sent anywhere — analysis happens entirely in your browser.

Module 03

Secure Password Generator

Choose a length and character categories, then generate a password guaranteed to include each selected type.

Options
How it works

The generator uses your browser's cryptographically secure random number source (crypto.getRandomValues), guarantees at least one character from every category you select, then shuffles the result so the guaranteed characters aren't always in the same position. No password is ever transmitted or stored.

Detection logic

The analyzer groups failed logins by IP address. Any IP that reaches 3 or more failed attempts is flagged as a likely brute-force source — a real system would typically follow this with rate limiting or a temporary IP block.

Detection logic

The analyzer groups failed logins by username and counts unique passwords attempted. Repeating the same wrong password isn't counted twice — but once a username has 3 or more distinct failed guesses, it's flagged as a likely password-guessing attack rather than an honest typo.

About this project

A browser-only authentication security lab

Built as a college project to demonstrate five common authentication defense concepts without any server, database, or external API.

What's inside

Every module — the password strength checker, login lockout simulator, password generator, brute-force detector, and password-guessing detector — runs on plain HTML, CSS, and JavaScript, all bundled into this single file. Open it directly in a browser, or deploy it as-is to GitHub Pages; there's nothing to install or configure.

Technology

HTML5, CSS3, and ES6 JavaScript only, all in one file. No frameworks, no build step, no dependencies beyond Google Fonts and Font Awesome for styling.

No backend

All "attacks" and login logs are predefined sample data baked into the page. Nothing is sent to a server, stored in a database, or persisted after you close the tab.

Purpose

Designed as an educational demo to make abstract authentication-security concepts — lockouts, brute force, credential stuffing — tangible and interactive.

Disclaimer

This toolkit is a teaching aid, not production security software. The login data, IP addresses, and "attacks" it detects are fixed sample datasets used purely to illustrate detection logic — nothing here connects to real systems or real credentials.
